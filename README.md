# jcode

Create, decode and edit Jew Code blocks ([DEP-0248](https://dep-specs.org/specs/rfc0248.html)) in the browser.
It's a static site with no build step and no dependencies, and it runs entirely client-side.

- **Create** (`create.html`) walks you through a series of questions and builds your block as you answer. It uses the same flow as
  omer's [jewcodegen](https://fergie.omer.land/omer/jewcodegen) CLI: background, denomination, heritage,
  practice, knowledge, identity, then family and community context. After each stage you can add more terms to an answer
  (`Bj^Bc`, `Sh+|Sh-`, `O<R>`, `[?K]!`, …), and at the end you can fine-tune salience, intensity, change over time
  and exceptions.
- **Decode** (`decode.html`) reads a pasted block token by token, checks each token with the same validator, and offers
  **Edit in Create**.
- **Edit** opens a decoded block in Create with every question prefilled. Tokens that the questions can't express are
  kept exactly as written. The original token order is preserved, and new or changed tokens are placed next to their
  category.

Answers live in the URL fragment (`create.html#p=…`), which browsers never send to the server. That makes a copied
edit link a full save file.

## Develop

```sh
python3 -m http.server 8000   # then open http://localhost:8000 (or just open index.html from disk)
npm run build                 # after editing js/: regenerates dist/
npm test                      # node --test, no dependencies; fails if dist/ is stale
```

The source is ES modules in `js/`. The pages load `dist/create.js` and `dist/decode.js` instead. These are classic
scripts generated by `scripts/bundle.mjs`, so the site also works when opened straight from disk. Commit `dist/` along
with `js/`.

## Layout

| Path | What |
|---|---|
| `js/jewcode.js` | Port of jewcodegen's `pkg/jcg/jewcode`: codes, token validation, profile → tokens, additions, groups |
| `js/wizard.js` | Create page: the question flow from `pkg/jcg/wizard` |
| `js/parse.js` | Block → profile (reverse of the builder), order preservation, validation helpers |
| `js/decode.js` | Decode page |
| `js/state.js` | Profile ⇄ URL fragment |
| `test/` | Ported Go test cases, plus parser and share-link round trips |

### How decoding maps to questions

Each token is matched against the patterns the builder produces. A match is accepted only if rebuilding from the
resulting answers reproduces exactly that token, so the parser never changes what someone wrote. Everything else goes
to the "kept as written" list, including hand-written forms the wizard wouldn't produce (such as `Tx->Tx+`, which the
builder writes as `Tx->+`) and custom expressions.

## Deploy

GitHub Pages: **Settings → Pages → Deploy from a branch → `main` / root**. The `.nojekyll` file stops Jekyll
from processing the site.
